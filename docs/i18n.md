# Bilingual UI — i18n architecture (`@xidig/i18n`)

Xidig is bilingual from day one (PRD §22): **Somali-first, English fallback**.
The architecture shipped in Phase 1; Somali coverage is tracked and climbs to
100% — trust-defining surfaces (navigation, onboarding, errors, empty states,
core actions) are the launch floor and are enforced at 100% by tests.

## The one rule

**UI copy never ships as a hardcoded string.** Every user-visible string is a
key in the `@xidig/i18n` dictionaries, rendered with `t(key, params)`. This is
enforced by the `xidig-i18n/no-hardcoded-copy` ESLint rule on all `.tsx` files
under `apps/*/src` and `packages/ui/src` — hardcoded JSX text or user-facing
attributes (`alt`, `placeholder`, `title`, `aria-label`, …) fail the lint.

Legitimate escapes (brand marks, untranslatable identifiers) need an
`eslint-disable-next-line xidig-i18n/no-hardcoded-copy` with a one-line
justification comment. Endonyms in the language toggle come from
`LOCALE_NAMES`, not literals, so they don't need an escape.

## Package layout

```
packages/i18n/src/
  locales.ts          Locale type, LOCALES, DEFAULT_LOCALE ('so'), negotiateLocale()
  cookie.ts           xidig_locale cookie (name, serialize, parse)
  messages.ts         Message / PluralMessage types
  dictionaries/en.ts  English — the dictionary of record; defines every key
  dictionaries/so.ts  Somali — typed subset of the English keys
  translate.ts        createTranslator(locale) → t(key, params)
  format.ts           formatNumber / formatDate (Intl) + formatRelativeTime (time.* keys)
  coverage.ts         coverage report + LAUNCH_FLOOR_NAMESPACES
  react.tsx           'use client' LocaleProvider, useT(), useLocale()
```

`@xidig/i18n` (the root export) is React-free — safe for server components,
API routes, scripts, and the future React Native app (API-first, §22). React
bindings are imported from `@xidig/i18n/react`.

## How to add a string

1. Add the key to `packages/i18n/src/dictionaries/en.ts` under the right
   namespace (see conventions below). English is the dictionary of record —
   a key that isn't in `en.ts` doesn't exist.
2. Add the Somali translation to `dictionaries/so.ts`. If you genuinely can't
   yet, you may ship without it — the UI falls back to English for that key —
   but keys in launch-floor namespaces **must** have Somali
   (`coverage.test.ts` fails otherwise).
3. Render it:
   - **Client component:** `const t = useT()` from `@xidig/i18n/react`.
   - **Server component:** `const t = await getT()` from `apps/web/src/lib/locale.ts`.
4. `pnpm i18n:coverage` shows the updated coverage table.

Never concatenate translated fragments — word order differs between Somali
and English. Use one key with `{param}` placeholders instead.

## Key naming conventions

- Format: `namespace.camelCaseName` (enforced by `coverage.test.ts`).
- Namespaces: `app` (identity), `nav` (canonical tabs), `term` (canonical
  product nouns), `action` (buttons/CTAs), `language`, `state`
  (loading/empty), `error` (§27 plain-language), `onboarding`, `a11y`
  (screen-reader-only), plus one namespace per screen (`home.…`).
- A new namespace must be classified in `coverage.test.ts`: launch floor
  (trust surface, Somali required) or tracked off-floor.
- Params are `{name}` placeholders; numbers are locale-formatted
  automatically.
- Messages that vary with a count are plural objects:
  `{ one: '{count} co-sign', other: '{count} co-signs' }`, selected by the
  required `params.count` (CLDR rules; English and Somali both use
  one/other).

## Language resolution & persistence

Resolution order per request (`apps/web/src/lib/locale.ts`):

1. **`xidig_locale` cookie** — set by the language toggle; 1-year Max-Age.
2. **`Accept-Language`** — quality-aware negotiation between `so` and `en`.
3. **Somali** (`DEFAULT_LOCALE`) — Somali-first product.

The toggle (`apps/web/src/components/language-toggle.tsx`) switches without a
page reload: the `LocaleProvider` re-renders client components immediately,
`router.refresh()` re-resolves server-rendered strings, and the choice is
persisted to the cookie (everyone) and to `users.preferred_language`
(signed-in members, best-effort — RLS self-row, column-granted).

**Open integration TODOs** (coordinate with the auth work):

  against the `LOCALES` union) and have the helper `fetch` it instead of
  writing `users` from the browser client. Same best-effort semantics.
- Decide the `users.preferred_language` column default: `'en'` today, which
  contradicts the Somali-first app default. Either flip the migration default
  to `'so'` or make the column nullable ("no explicit choice") — the sign-in
  hydration sites already guard with `isLocale(...)`, so null is safe there.
- On sign-up, write the active session locale to `users.preferred_language`

## Coverage tracking

- `pnpm i18n:coverage` prints per-namespace Somali coverage and the exact
  missing keys.
- `coverage.test.ts` (runs in `pnpm test` / CI) **fails** if a launch-floor
  namespace is not 100% Somali, if a Somali key doesn't exist in English, if
  placeholders diverge between languages, or if plural shapes diverge.
- Off-floor gaps never fail the build — English fallback keeps the UI whole,
  and the report is how coverage climbs to 100% post-launch.

## Formatting helpers

`formatNumber` and `formatDate` wrap `Intl` with the active locale.
`formatRelativeTime` deliberately does not — see the next section. Use all three
instead of `toLocaleString()` so the locale always comes from one place, and so
a bad argument degrades instead of throwing.

Missing Somali CLDR data is _not_ what the two `Intl` helpers guard against:
`Intl` never throws over it, and a well-formed tag silently resolves to the host
default. What can throw is the caller's own options — an invalid `timeZone`, a
`currency` style with no currency code — so each of those two retries once with
the options dropped and the locale kept, then degrades (`formatDate` to `—`,
`formatNumber` to the bare number).

Options are dropped **wholesale**, not repaired, so the degradation is lossier
than "same value, plainer format": a `{ dateStyle, timeStyle, timeZone }` call
that trips on the zone loses the clock time altogether ("04-Lul-2026 ee 12:00
GD" → "04-Lul-2026"), and a dropped `style` shows an unscaled number (0.5 as
"0.5", not "50%"). It is silent in both cases. Callers that need their options
honoured must validate them (see `isValidTimezone`).

### Relative time is dictionary-owned — never `Intl.RelativeTimeFormat`

`formatRelativeTime` reads `time.*` keys from the dictionaries and touches
`Intl` nowhere. This is a rule, not an implementation detail, and reaching for
`Intl.RelativeTimeFormat` will reintroduce a bug that took a release to find.

The reason is the same silent resolution described above, turned hazard: on a
runtime whose ICU lacks Somali, `Intl.RelativeTimeFormat('so')` throws nothing —
it quietly returns the **host default**. A server built without Somali CLDR
therefore rendered English while the browser rendered Somali, so every Somali
time node hydration-mismatched, with no error anywhere to point at the cause.

Dictionary-owned copy gives server and client one data source on every runtime.
The consequence for contributors: a new relative-time string is a new `time.*`
key in both dictionaries, never a call into `Intl`.

## Adding a locale (future — EN/SO are the only launch languages)

Not planned for v1.0, and adding one is a product decision first (§25.5: no
global launch features without approval). When it IS approved, the plumbing is
deliberately additive; the checklist is the whole job:

1. **Register the dictionary** — add `dictionaries/<locale>.ts` and extend
   `LOCALES`. The compiler then forces the rest: `translate.ts`'s
   `Record<Locale, PartialDictionary>` and `format.ts`'s `partials`
   (`Record<Exclude<Locale, 'en'>, …>` — the hydration-critical relative-time
   path; it was made compile-enforced precisely so a new locale cannot silently
   render English timestamps).
2. **Plural forms** — `PluralMessage` is `{one, other}`, sufficient for EN/SO.
   A locale with more categories (e.g. Arabic) needs the message shape widened
   first; do it in the package, not per-call-site.
3. **Label columns** — add nullable `name_<locale>` columns to the seeded
   lookup tables (`lanes`, `listing_categories`, `event_categories`) and
   backfill; extend the `{en, so}` payload types additively.
4. **Fold sites** — `grep -rn "=== 'so'"` across `apps/web` and widen each
   display-side name fold (they fail soft — English shows — but do the sweep).
5. **Coverage gates** — extend the coverage floor/vocabulary machinery in
   `packages/i18n/src/coverage.ts` so the new locale is visible to the build
   gates, or its gaps will never surface.
6. **OG/alternates** — the OG `alternateLocale` computation assumes "the other
   locale" in a two-member set; generalize it when the set grows.
